# qcg clients

Generated by `scripts/generate-sdk.mjs` from `docs/openapi.json`.

- `ts/` — dependency-free TypeScript client and generated OpenAPI types.
- `python/qcg_client.py` — dependency-free Python client (stdlib only).

Regenerate with `node scripts/generate-sdk.mjs`; `scripts/check-sdk.sh`
fails CI when the checked-in clients are stale or fail strict TypeScript
typechecking (using the existing frontend TypeScript compiler), and
`scripts/check-sdk-behavior.sh` proves runtime behavior (SSE delivery and
framing, redirect bounds, typed readers, HTTP problem errors). Both clients
send the bearer token only as an Authorization header and never place it
in a URL.
Authenticated redirects strip the bearer cross-origin and on TLS
downgrades; path wildcards encode segment by segment.

HTTP errors (TypeScript): `QcgError` retains the HTTP status and original
parsed problem as `unknown`. The message uses a nonempty string `detail`,
then a nonempty string `title`, then the response's `statusText`. Non-JSON
bodies are retained as `{ detail: text }`; an empty body becomes `{}`.
Wrong-type message properties and primitive JSON are not coerced to strings.

Redirects (TypeScript): manual same-protocol/cross-origin redirects are
followed up to 5 hops with cycle detection; anything further fails with a
clear redirect error instead of looping. Intermediate responses are
released before following. Relative request URLs (default same-origin
`/api/...`) resolve against the configured base URL, the document base
in browsers, or a dummy origin in Node purely for URL resolution.
Browser opaque-redirect responses expose no Location header and therefore
surface as HTTP errors rather than silent follows.

SSE (both clients): utilizable bytes are consumed incrementally (Python
uses read1 so flushed tens-of-bytes events arrive while the stream stays
open). CR immediately ends a line; one following LF is swallowed across
chunk boundaries, so split CRLF is one break. Multi-data lines join with LF;
an EOF without a terminating blank line dispatches only already-terminated
frames and never fabricates an event from the tail. Python's
`stream_run_events` is a generator: after an early exit, explicitly close
it, for example with `contextlib.closing(client.stream_run_events(run_id))`
to release the response. TypeScript's async generator releases its reader
when the consumer returns early; parse failures also run its cleanup.

Run snapshots expose `queue_position_quality`: `exact`, `estimated`, or
`unavailable`. Python returns the same fields in dictionaries. Transport
markers `lagged`, `stream_error`, and `shutdown` do not advance a
reconnection cursor; use the last actual run-event sequence.
